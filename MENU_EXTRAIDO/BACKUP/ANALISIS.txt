1. RESUMEN EJECUTIVO
--------------------------------------------------------------------------------
ARCHIVO DEL MENÚ: c:\Users\PC\Downloads\VIDEO\MENU_EXTRAIDO\lucidgfx_overlay.html
ORIGEN EN BINARIO: c:\Users\PC\Downloads\VIDEO\dxgi.dll (Offset RVA: 0x176870)
TECNOLOGÍA: HTML5 + CSS3 + JavaScript puro embebido + Microsoft Edge WebView2

La interfaz que aparece en la captura NO es un ejecutable independiente ni un recurso
estándar de Windows (tipo .rsrc). Está construida como una Single Page Application (SPA)
en HTML5, estilizada con CSS moderno (dark mode, glassmorphism, flexbox) y controlada
mediante JavaScript. 

El archivo HTML original estaba integrado y OFUSCADO dentro del archivo 'dxgi.dll'
utilizando un cifrado XOR de doble clave (Dual-Key XOR de 64 bytes) para evitar su
extracción simple.

Hemos descifrado y extraído el 100% de la interfaz original a la carpeta 'MENU_EXTRAIDO'.

3. MAPEO DE COMPONENTES DEL MENÚ (¿QUÉ ARCHIVO CONTROLA CADA PARTE?)
--------------------------------------------------------------------------------
* ¿Qué archivo controla la ESTRUCTURA HTML?:
  -> MENU_EXTRAIDO/lucidgfx_overlay.html
  -> Define los contenedores, encabezado "GFXMods v1.1.2", banner de actualización,
     pestañas ("Multimídia", "Config", "Licença", "Links"), tarjetas de "Comunidade"
     (Instagram, Discord), controles de estado y sliders.

* ¿Qué archivo controla los ESTILOS CSS?:
  -> MENU_EXTRAIDO/overlay_styles.css (y dentro de <style> en lucidgfx_overlay.html)
  -> Controla la paleta de colores azul oscuro/morado (#0a0e1a, #1a2238),
     efectos hover, estilos de botones, badges de status ("Parado", "Ativo") y sliders.

* ¿Qué archivo controla la LÓGICA JAVASCRIPT?:
  -> MENU_EXTRAIDO/overlay_script.js (y dentro de <script> en lucidgfx_overlay.html)
  -> Gestiona el cambio de pestañas, la lectura/escritura de valores de zoom y volumen,
     el cambio de estado del botón INICIAR/PARAR y la comunicación con el host C++.

* ¿Qué archivo controla las IMÁGENES / ICONOS?:
  -> Incrustados directamente en 'lucidgfx_overlay.html' como SVG inline y datos Base64
     para que la interfaz no requiera archivos de imagen externos en disco.

* ¿Qué archivo controla las FUNCIONES DE LOS BOTONES?:
  -> Controladas por JavaScript en 'lucidgfx_overlay.html' / 'overlay_script.js'.
  -> La comunicación con el juego/DLL se realiza mediante el protocolo personalizado:
     'lucidgfx://action/[nombre_accion]' interceptado por WebView2 en 'dxgi.dll'.

* ¿Qué archivo controla el TEXTO MOSTRADO?:
  -> 100% editable en 'MENU_EXTRAIDO/lucidgfx_overlay.html'.


4. CONTENEDORES Y MÉTODOS DE EMPAQUETADO DETECTADOS
--------------------------------------------------------------------------------
* ¿Existe código empaquetado / minificado?: 
  NO. El código HTML/JS/CSS extraído está en texto plano legible, con nombres de
  funciones claros y estructura limpia (no está ofuscado con Webpack/Terser).

* ¿Existe código compilado?:
  La DLL 'dxgi.dll' contiene el motor DirectX 11 y el host de WebView2 compilado en C++,
  pero la interfaz visual en sí se ejecuta como HTML/JS en el motor WebView2.

* ¿Existe algún archivo .pak, .asar, .dat, .bin?:
  Los assets estaban empacados internamente en la sección '.rdata' de 'dxgi.dll'
  en una tabla de recursos estructurada en la dirección VA 0x180190E40 y cifrada con
  XOR de doble clave (64 bytes cada una). Ya han sido completamente descifrados.


5. CÓMO MODIFICAR POSTERIORMENTE ESTE MENÚ
--------------------------------------------------------------------------------
Puedes editar directamente los archivos dentro de 'MENU_EXTRAIDO/':

1. Edición visual y de textos:
   Abre 'MENU_EXTRAIDO/lucidgfx_overlay.html' en tu editor de código para cambiar:
   - Textos (ej: títulos, descripciones, botones).
   - Enlaces de redes sociales (Instagram, Discord).
   - Colores y diseño en la sección <style> o 'overlay_styles.css'.
   - Opciones y valores por defecto.

2. Previsualización inmediata:
   Puedes hacer doble clic en 'lucidgfx_overlay.html' para abrirlo en cualquier
   navegador (Edge, Chrome, Firefox) y ver exactamente cómo se ve y responde la interfaz.

3. Re-inyección (en fase posterior):
   Una vez editado el HTML, se puede volver a empacar/cifrar dentro de 'dxgi.dll'
   o configurar el host para cargar los archivos directamente desde una carpeta local.
